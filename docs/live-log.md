# Live sessions: the log convention

Every live session on a real timer (a practice night, RaceGOW, a club event) gets one
GitHub issue, opened before the session, titled like
`<event>: live log (<plugin version>)`. Issue #19 (RaceGOW6 track 2, 0.3.0) is the model.

- **Reports go in verbatim.** Each thing Ryan notices is a comment quoting what he said,
  with the page and the time. Our own read of the cause goes under the quote, marked as a
  guess until verified.
- **Nothing is fixed mid-session** except what blocks the session. A mid-session fix is a
  comment of its own with the version that shipped it.
- **Afterwards, every item is filed** into a tier's issue (the plan, #2), or closed with a
  reason. The log issue is closed with a list of where each item went.
- **The tier's checklist result** (`rehearsal.md`) is a comment on the tier issue, with
  the log issue linked, so the tier's "live" gate has a record.

Things worth watching in every session, until the tier that owns them closes: the start
lining up with the tones, lap latency on the overlay against the Run page, anything that
made RotorHazard's own page necessary.
